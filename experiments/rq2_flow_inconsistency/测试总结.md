# RQ2 流程不一致性检测实验 - 测试总结

## 实验概述

**RQ2: Flow Inconsistency Detection（流程不一致性检测）**

该实验评估 GUIPilot 在检测移动应用流程不一致性方面的能力。与 RQ1 的屏幕不一致性检测不同，RQ2 关注的是操作后 UI 转换流程的一致性，即检测实际 UI 转换是否与预期的 mockup 设计一致。

## 测试日期

2025年11月6日

## 实验目标

RQ2 实验的主要目标是：
1. 检测操作后实际屏幕转换与预期 mockup 屏幕之间的不一致性
2. 使用 Vision-Language Model (VLM) 代理来自动完成操作
3. 评估 GUIPilot 在流程一致性检测方面的有效性

## 实验流程

### 主要步骤

1. **初始化**
   - 加载数据集路径
   - 初始化 Matcher (GUIPilotV2)
   - 初始化 Checker (GVT)
   - 初始化 Automator (Android 设备控制)
   - 初始化 GPTAgent (VLM 代理)

2. **遍历流程**
   - 对每个 `process_*` 目录：
     - 加载 `record.json` 文件
     - 随机选择一个步骤作为不一致性注入点
     - 启动应用

3. **执行步骤**
   - 对每个步骤：
     - 获取预期的 mock 屏幕
     - 执行操作（自动或手动）
     - 获取实际的真实屏幕
     - 匹配 widgets 并检查不一致性
     - 如果检测到不一致性，使用 VLM 代理进行修复

4. **VLM 代理修复**
   - 当检测到不一致性时：
     - 回退到上一个屏幕
     - 使用 VLM 代理分析当前屏幕
     - 生成操作来完成预期流程
     - 验证操作是否正确

5. **结果记录**
   - 保存可视化结果
   - 记录性能指标
   - 记录完成状态

## 代码结构

### 主要文件

- **main.py**: 主实验脚本
- **actions/automator.py**: Android 设备自动化控制
- **actions/recorder.py**: 记录和步骤定义
- **actions/translator.py**: 操作翻译
- **utils.py**: 工具函数（屏幕获取、评分、可视化等）
- **action_completion.user.prompt**: VLM 代理的提示模板

### 关键类和方法

1. **Automator**: Android 设备控制
   - `launch()`: 启动应用
   - `click()`: 点击操作
   - `back()`: 返回操作
   - `send_keys()`: 输入文本
   - 等等

2. **Record/Step**: 数据模型
   - `Record`: 包含完整的流程记录
   - `Step`: 单个步骤的信息

3. **GPTAgent**: VLM 代理
   - 用于分析屏幕并生成操作

## 预期输出

### 结果文件

实验会在 `results-<timestamp>/` 目录下生成：

1. **results.txt**: CSV 格式的结果文件
   - 包含每个步骤的评分、时间、完成状态等

2. **可视化图片**:
   - `{package_name}-{process_no}/{step}.jpg`: 每个步骤的可视化
   - `{package_name}-{process_no}/{step}-inconsistent.jpg`: 不一致性检测结果

3. **文本文件**:
   - `{package_name}-{process_no}/{step}-inconsistent.txt`: VLM 代理的响应

### 结果指标

- **score1, score2, score3**: 不同的评分指标
- **action_time**: 操作执行时间
- **time1, time2, time3**: 不同阶段的处理时间
- **ground_truth**: 是否真的存在不一致性
- **is_completed**: VLM 代理是否成功完成操作
- **retries**: 重试次数

## 与 RQ1 的区别

## 常见问题

### Q1: 如何修改设备连接地址？

**A**: 修改 `actions/automator.py` 第 22 行：
```python
device: Device = u2.connect("your_device_ip:5555")
```

或者通过环境变量配置（需要修改代码支持）。

### Q2: record.json 文件格式是什么？

**A**: 参考 `actions/recorder.py` 中的 `Record` 和 `Step` 类定义。主要字段：
- `package_name`: 应用包名
- `init_activity`: 初始 Activity
- `steps`: 步骤列表，每个步骤包含 activity, screenshot, description, layout, action, params 等

### Q3: 实验需要多长时间？

**A**: 取决于：
- 流程步骤数量
- VLM 代理响应时间
- 手动交互时间
- 每个步骤的处理时间

预计每个流程需要 10-30 分钟（包括手动交互）。

### Q4: 可以自动化所有手动交互吗？

**A**: 理论上可以，但需要：
- 修改代码移除 `input()` 调用
- 实现自动屏幕对齐检测
- 实现自动操作验证逻辑

但这样可能会影响实验的准确性和可控性。
