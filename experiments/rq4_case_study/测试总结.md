# RQ4 案例研究实验 - 测试总结

## 实验概述

**RQ4: Case Study（案例研究）**

该实验是一个综合性的案例研究，结合了屏幕不一致性检测和流程不一致性检测。它评估 GUIPilot 在实际应用场景中的表现，包括：

1. **屏幕一致性检测**: 比较 mockup 设计屏幕与实际实现屏幕
2. **操作完成**: 使用 Vision-Language Model (VLM) 代理根据自然语言描述生成操作
3. **操作验证**: 验证 VLM 生成的操作是否正确

## 测试日期

2025年11月6日

## 实验目标

RQ4 实验的主要目标是：
1. 检测 mockup 屏幕与实际实现屏幕之间的不一致性
2. 使用 VLM 代理根据自然语言描述自动生成操作
3. 验证生成的操作是否与预期操作一致
4. 评估 GUIPilot 在真实案例中的综合表现

## 实验流程

### 主要步骤

1. **初始化**
   - 加载数据集路径
   - 初始化 Matcher (GUIPilotV2)
   - 初始化 Checker (GVT)
   - 初始化 GPTAgent (VLM 代理)

2. **遍历流程**
   - 对每个包含 `mockup` 目录的 process：
     - 加载 `implementation/process.json` 文件
     - 获取 mockup 和 implementation 路径

3. **处理步骤**
   - 对每个步骤（当前代码中只处理第 5 步，`if s != 4: continue`）：
     - 加载 mockup 屏幕（.png 格式）
     - 加载实际实现屏幕（.jpg 格式）
     - 匹配 widgets 并检查不一致性
     - 使用 VLM 代理根据 mock_actions 生成操作
     - 验证生成的操作是否与真实操作一致

4. **VLM 操作生成**
   - 使用 GPTAgent 分析当前屏幕
   - 根据自然语言描述（mock_actions）生成操作
   - 最多尝试 3 次，直到生成正确的操作

5. **结果保存**
   - 保存可视化图片
   - 生成 JSON 格式的报告

## 代码结构

### 主要文件

- **main.py**: 主实验脚本
  - 遍历所有 process 目录
  - 处理每个步骤
  - 调用 VLM 代理生成操作
  - 保存结果

- **utils.py**: 工具函数
  - `get_screen()`: 加载屏幕并执行检测和 OCR
  - `get_scores()`: 计算一致性分数
  - `get_action_completion()`: 使用 VLM 生成操作
  - `visualize()`: 生成可视化图片
  - `get_report()`: 生成 JSON 报告

- **actions/translator.py**: 操作翻译器
  - 将 widget ID 转换为边界框
  - 支持 click, long_click, send_keys, scroll, swipe, drag 等操作

- **action_completion.user.prompt**: VLM 提示模板
  - 包含操作生成的提示文本
  - 使用 `{ACTION_DESCRIPTION}` 占位符

### 关键功能

1. **屏幕匹配和检查**
   ```python
   pairs, score, match_time = get_scores(mock_screen, real_screen, matcher)
   inconsistencies, check_time = checker.check(mock_screen, real_screen, pairs)
   ```

2. **VLM 操作生成**
   ```python
   agent_image, action_names, actions_raw, actions = get_action_completion(
       agent, real_screen, mock_actions
   )
   ```

3. **操作验证**
   ```python
   action_correct = all([
       check_action(true_action, action_name, action)
       for true_action, action_name, action in zip(true_actions, action_names, actions)
   ])
   ```

## 预期输出

### 结果文件

实验会在 `output/` 目录下生成：

1. **可视化图片**:
   - `output/process{p}/screen{s}/image.jpg`: 原始对比图片
   - `output/process{p}/screen{s}/image_bbox.jpg`: 边界框标注图片
   - `output/process{p}/screen{s}/image_match.jpg`: 匹配结果图片
   - `output/process{p}/screen{s}/image_agent.jpg`: VLM 代理分析图片

2. **报告文件**:
   - `output/process{p}/screen{s}/report.json`: JSON 格式的详细报告
     - 包含匹配时间、检查时间
     - 包含匹配的 widget 对
     - 包含检测到的不一致性
     - 包含 VLM 操作生成结果

### 报告内容

报告 JSON 包含以下字段：
- `process`: 流程 ID
- `screen`: 屏幕 ID
- `match_time`: 匹配时间（毫秒）
- `check_time`: 检查时间（毫秒）
- `pairs`: 匹配的 widget 对列表
  - `ids`: widget ID 对
  - `inconsistencies`: 不一致性类型列表（如果有）
- `missing`: 缺失的 widget ID 列表
- `extra`: 额外的 widget ID 列表
- `action_correct`: VLM 生成的操作是否正确
- `action_trials`: VLM 尝试的操作列表（最多 3 次）

## 常见问题

### Q1: process.json 文件格式是什么？

**A**: `process.json` 应该是一个 JSON 数组，每个元素代表一个步骤：
```json
[
  {
    "screen": "1.jpg",
    "mock_actions": ["Click on button", "Enter text"],
    "actions": [
      {"type": "click", "params": {"id": 5}},
      {"type": "send_keys", "params": {"text": "hello"}}
    ]
  }
]
```

### Q2: mockup 和 implementation 屏幕格式要求？

**A**:
- Mockup 屏幕: `.png` 格式
- Implementation 屏幕: `.jpg` 格式
- 文件名应该对应（如 mockup 的 `1.png` 对应 implementation 的 `1.jpg`）

### Q3: 实验需要多长时间？

**A**: 取决于：
- 流程数量
- 每个流程的步骤数
- VLM 代理响应时间
- 屏幕复杂度

预计每个步骤需要 1-5 分钟（包括 VLM 调用）。

### Q4: 如何修改处理的步骤？

**A**: 修改 `main.py` 第 45 行：
```python
# 处理所有步骤
# if s != 4: continue

# 或处理特定步骤
if s not in [4, 5, 6]: continue  # 只处理第 5、6、7 步
```
